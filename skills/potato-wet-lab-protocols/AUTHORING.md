# 湿实验方法技能编写原则

本文件用于指导本目录内 Hermes Lite 湿实验技能的创建和维护。以 [植物基因组 DNA 提取技能](plant-genomic-dna-extraction/SKILL.md) 及其 `references/` 的当前内容为结构和文风示例。编写前先读取现有文件，保留用户已经确认和修改的内容。

目标是让智能体按需读取方法，为实验用户提供清晰的准备清单、操作流程和周期估算。面向实验用户的要求应写入具体技能，不能只留在本编写原则中。

## 文件组织与 Hermes 格式

一种实验方法建立一个独立技能。同一方法的不同规格或处理方式放在该技能的参考文件中：

```text
potato-wet-lab-protocols/
  DESCRIPTION.md
  AUTHORING.md
  <skill-name>/
    SKILL.md
    references/
      <variant-a>.md
      <variant-b>.md
      reagents.md
```

- `SKILL.md` 放用途、输入、规格选择、准备要求、周期汇总、检测保存和参考文献。
- 每个规格的参考文件放相应材料、仪器、耗材、试剂、完整操作及时间核算；单规格方法可使用 `references/protocol.md`。
- 共用配方集中在 `references/reagents.md`，按需链接，不在各规格重复整张配方表。没有配方时不创建空文件。
- 只添加实际需要的文件，不创建空目录、重复说明或与方法无关的脚本。
- 所有参考文件使用相对链接，并在入口说明何时读取。先选规格，再加载对应文件；仅查询配方时加载配方文件，不要求读完所有规格。

沿用 Hermes 的 YAML frontmatter，例如：

```yaml
---
name: plant-method-name
description: 用一句话说明具体实验方法及适用任务。
version: 1.0.0
author: Potato Agent
metadata:
  hermes:
    tags: [plant, wet-lab, protocol]
---
```

技能目录名与 `name` 一致，使用小写字母、数字和连字符，不超过 64 个字符。`description` 不超过 1024 个字符，优先控制在 60 个字符内，让方法名称和用途在简短索引中可见；标签按实际方法填写。

按 Hermes 调用方式提供文件入口：`skill_view(name="技能名", file_path="references/文件名.md")`。技能不依赖编写者的临时目录、个人路径或原始文档所在位置。

## 文档结构与表达

入口通常按“适用范围与输入、规格选择与按需读取、实验前准备、周期估算、检测与保存、方法来源文献”组织；简单内容可以合并，避免空标题。

规格文件通常按“材料、仪器、耗材与试剂，操作步骤，必要的操作注意或分支安排，定时步骤核算”组织。采用中文短句；步骤用有序列表，规格比较、用量和配方用表格。

每步写清动作、用量和必要条件，包括时间、温度、转速、混匀方式、保留上清或沉淀等。可选步骤写明分支及跳转位置。检测与保存简述取样量、仪器或方法、检测项目和保存条件，不堆砌质量讨论。

直接写实验方法，不写“根据用户提供的某文档整理”、原文件名、PDF/OCR/视觉校对过程或编辑历史。删除重复背景、来源声明、冗长免责声明及已解决的待确认说明。

## 实验前准备

生成的技能必须要求智能体在给出完整流程或排期时，先提醒用户备齐材料与设备，并检查实验开始前的就绪条件。将这些准备事项单独列出，不混入提取、反应等主体操作步骤；具体步骤仍保留必要的使用条件。

按方法实际需要覆盖以下项目，不要求每种方法机械填满所有类别：

| 类别 | 应写明的内容 |
| --- | --- |
| 实验材料 | 材料类型与状态、单样本用量、样本数，以及需要提前完成的培养、取样等准备 |
| 仪器 | 所需仪器、关键性能、匹配转子或适配器、单批容量；必要时提醒预约和可用时段 |
| 耗材 | 管、板、盖、吸头等的规格、工作容量、数量及必要的无菌等要求 |
| 试剂 | 名称、浓度、单样本用量和批量需求，哪些需提前配制、解冻或分装 |
| 就绪条件 | 方法要求的预热、预冷、灭菌、仪器校准、标记和孔位安排，以及必要的工作环境 |

从步骤中补出明确必需的设备和耗材。例如，步骤使用预冷离心管时，准备清单应提醒提前预冷；检测步骤使用 NanoDrop 时，仪器清单应包含 NanoDrop。不要只写“准备常规实验器材”。

区分单样本、单孔与整批用量；耗材按实际转移次数核算。批量试剂需求与额外余量分开，余量注明依据或假设。仅查询某个配方或步骤时，提醒与该问题相关的准备事项即可。

## 实验参数与配方

方法参数依据实验资料及用户明确的修订填写。已确认的参数直接采用，不反复追问或重新讨论其定义。DNA 提取技能仅作为结构和文风示例，其中的试剂、温度、转速及保存条件不作为其他方法的默认参数。

保持参数含义和单位一致，不把 rpm 直接改成同数值的相对离心力。不同规格分别保留各自参数，不按容器大小简单倍增整套流程。仪器相关设置按方法要求及实际设备性能填写。

配方注明终体积、组分、母液浓度或化学形式、用量、终浓度及必要的配制顺序。区分起始加水与最终定容；pH 调节以目标 pH 为准。母液与工作液之间有准备依赖时，应让读者能找到所需母液配方。

缺少影响操作或周期的关键参数时，不编造数值；在相应位置简短指出需要补充的内容，继续整理已有信息。不要将其扩写为通用的长篇“信息缺口”章节。

## 实验周期

每个技能必须在 `SKILL.md` 中写明周期，并在对应规格文件中保留可核对的时间计算。周期至少说明起点、终点、单批规模、所选分支以及估算前提，例如“材料和试剂已备齐，从开始处理样本到检测完成”。

- 分别识别实验前准备、人工操作、设备运行、培养或等待、检测及保存处理所需时间。耗时缺少依据时明确未计入或列为估算假设。
- 已有定时步骤给出小计或有依据的范围；入口汇总与规格文件计算保持一致。仅有定时小计时明确它不等于完整周期。
- 仪器预约、材料培养、配液、预冷或预热等准备若影响实验开始，应单列其提前量；不能在总周期中悄悄省略。
- 按样本数、单批容量、设备数量和人员安排评估批次。共用水浴或离心时间不简单乘以样本数；人工移液等工作量也不能忽略。
- 串行依赖按顺序计算；只有设备、人员和方法允许时才安排并行，按实际依赖确定完成时间，避免重复加总重叠时段。
- 可选步骤分别给出耗时；过夜或跨日步骤说明从哪一步暂停、何时继续，以及方法要求的保存条件，不自行添加未经确认的暂停点。
- 修改操作时长、步骤顺序或分支后，同步更新所有时间表。新增的缓冲时间或操作时间注明依据，不写成方法规定值。

向实验用户解释周期时，优先回答需要多少小时或多少天、是否跨日、哪些准备应提前完成，再简述主要耗时阶段和估算条件。

## 参考文献

在 `SKILL.md` 的“方法来源文献”中列出用户提供的原始文献，包括作者、年份、题名、期刊、卷期、页码或文章号及 DOI 链接。资料缺项时不编造。多个规格共用文献时不重复列出相同条目。

方法经过调整时可简述“参考以下文献并作调整”，无需说明由哪个中间文档改写而来，也不要将调整后的全部参数宣称为文献原值。

## 完成检查

1. 核对所有规格的步骤、用量、单位、分支、检测与保存条件，确认入口和参考文件一致，保留用户已有修改。
2. 对照操作步骤检查准备清单，确认必需仪器、耗材、试剂及提前准备事项没有遗漏。
3. 重算各规格与分支的定时小计，核对批次、并行、跨日安排及未计入时间。
4. 检查文献和相对链接，删除冗余说明、空模板和已解决的待确认项。
5. 新建或调整技能结构时，用 Hermes Lite 的 `_validate_name`、`_validate_frontmatter`、`_validate_content_size` 校验，并在隔离的 `HERMES_HOME` 中检查技能发现及 `skill_view` 按需加载。小范围文字调整只做相应内容与链接检查。

编写工作在本仓库完成；技能分发和生产部署遵循仓库的部署约定。
